# INF Editor — оснастка MMC для INF-файлов драйверов

Редактор INF-файлов драйверов Windows в виде оснастки консоли управления (MMC), как `gpedit.msc` или `certmgr.msc`.
Открывается файлом `inf_editor.msc`. По назначению близок к GenInf из Windows DDK, но умеет не только создавать
INF, а открывать, разбирать, проверять и править существующие файлы.

## Возможности

- **Дерево пакета драйвера.** Для каждого открытого файла показываются:
  - версия `[Version]`;
  - производители и устройства;
  - все секции с ролями и связями;
  - строки `[Strings]` и их локализации;
  - копируемые файлы;
  - проблемы.
- **Окна свойств.** Через свойства правятся:
  - `[Version]`: класс с GUID, поставщик, DriverVer, каталог, PnpLockdown;
  - модель устройства: описание, ID оборудования, секция установки;
  - любая запись секции, строковая константа, кодировка и концы строк файла.
- **Команды контекстного меню и панели «Действия».** Можно:
  - добавить устройство, запись, секцию, строку, язык (`[Strings.LLLL]`) или файл пакета;
  - переименовать секцию; ссылки на неё обновляются автоматически;
  - удалить секцию, запись, устройство или строку;
  - удалить неиспользуемые строки или добавить неопределённые;
  - обновить DriverVer;
  - отменить или повторить изменение.
- **Редактор текста** файла целиком или одной секции: подсветка синтаксиса, поиск, проверка и переход к строкам с проблемами.
- **Проверка** синтаксиса, ссылок между секциями, строк `%ключ%`, моделей, служб, файлов и записей реестра.
  Кроме того, можно запустить InfVerif из Windows Driver Kit для текущего, в том числе несохранённого, текста.
- **Мастер создания INF.** Поддерживаемые типы пакетов: KMDF, UMDF 2, WDM, WinUSB, устройство без драйвера,
  Extension INF и служба без Plug and Play.
- **Сохранение без потерь.** Сохраняются кодировка (ANSI, UTF-8, UTF-8 BOM, UTF-16 LE/BE), BOM, концы строк,
  завершающий Ctrl+Z, комментарии и форматирование. Изменения затрагивают только нужные строки. Файл, открытый
  и сохранённый без правок, совпадает с исходным байт в байт; это проверено на всех INF из `C:\Windows\INF`.
  Исключение — файлы со смешанными концами строк: при сохранении они приводятся к одному виду.
- **Устройства компьютера.** Ветка повторяет Диспетчер устройств: устройства по классам, их драйверы, INF и
  признак стороннего пакета. Для устройства доступны команды:
  - «Открыть INF драйвера» в редакторе;
  - «Экспортировать драйвер в CAB»;
  - «Показать пакет в Проводнике»;
  - «Создать INF для этого устройства» — мастер с подставленными ID оборудования, классом и производителем;
  - «Копировать ID оборудования».
- **Пакеты драйверов.** Ветка показывает сторонние пакеты хранилища драйверов (опубликованные как `oemNN.inf`).
  Каждый пакет можно экспортировать в CAB, а все сразу — командой «Экспортировать все сторонние драйверы».
- **Сессия.** Список открытых файлов восстанавливается при следующем запуске консоли.

## Экспорт драйвера в CAB

Сторонним считается пакет, опубликованный в `%SystemRoot%\INF` под именем `oemNN.inf`. Драйверы, которые
установил Windows Update, тоже относятся к таким: это пакеты производителей. При экспорте предлагается два режима:

- **Все файлы в корень архива** (по умолчанию). В архив попадают INF, все файлы из `[SourceDisksFiles*]`
  и каталоги подписи, причём все в корень. В INF очищаются пути в `[SourceDisksNames*]` и поддиректории
  в `[SourceDisksFiles*]`, поэтому после распаковки INF берёт файлы из той же директории.
  - Файлы из разных поддиректорий могут совпадать по имени при разном содержимом (например, `x86\a.sys`
    и `amd64\a.sys`). Такой пакет уложить в корень нельзя, экспорт сообщает об этом.
  - Каталог `.cat` содержит хеш исходного INF, поэтому подпись для изменённого INF недействительна.
    Перед установкой пакет необходимо переподписать (`inf2cat` и `signtool`) или включить тестовый режим.
- **Пакет без изменений.** Архив повторяет директорию пакета в хранилище драйверов, INF не меняется,
  подпись остаётся действительной.

В хранилище драйверов Windows оставляет только файлы для своей платформы, поэтому файлы других архитектур,
упомянутые в INF, в архив не попадают. Экспорт выводит их списком.

## Состав

| Путь | Назначение |
|---|---|
| `src/core` | Ядро на стандартном C++20 без зависимостей от интерфейса: разбор, модель, проверка, правка, генерация, InfVerif |
| `src/snapin` | Оснастка MMC: COM-объекты (`IComponentData`, `IComponent`, `IDataObject`, `ISnapinAbout`), окна свойств и диалоги на MFC |
| `tests` | Тесты ядра (консольная программа) |
| `tools` | Регистрация оснастки и создание `inf_editor.msc` |
| `inf_editor.msc` | Файл консоли |

## Сборка

Необходимы Visual Studio 2022 с компонентами «Разработка классических приложений на C++» и «MFC для v143»,
а также CMake 3.21 или новее.

```bash
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
```

```bash
cmake --build build --config Release
```

Результат: `build\Release\inf_snapin.dll` (оснастка) и `build\Release\inf_editor_tests.exe` (тесты).

Для проверки ядра необходимо запустить тесты:

```bash
build\Release\inf_editor_tests.exe
```

Тест `generatedPassesInfVerif` выполняется, только если установлен WDK, иначе он пропускается.

## Установка

Оснастку необходимо зарегистрировать от имени администратора: MMC читает список оснасток из `HKLM`.

```bash
tools\install.cmd
```

Скрипт регистрирует `build\Release\inf_snapin.dll` через `regsvr32`, заново создаёт `inf_editor.msc`
и записывает её путь в `HKLM\Software\Microsoft\Windows\CurrentVersion\App Paths\inf_editor.msc`. Путь
к DLL можно передать первым параметром. Для отмены регистрации используется `tools\uninstall.cmd`.

После регистрации консоль запускается командой `inf_editor.msc` в окне «Пуск → Выполнить» (Win+R), как
`devmgmt.msc` или `gpedit.msc`, а также двойным щелчком по файлу. Консоль однооконная: команды «Новое окно
отсюда» и меню «Окно» в ней нет. Оснастку также можно добавить в любую консоль через «Файл → Добавить или
удалить оснастку → Редактор INF».

Для работы нужна среда выполнения Visual C++ 2015–2022 x64 (`mfc140u.dll`, `vcruntime140.dll`).

## Работа с файлами

- **Открытие и создание.** Команды «Открыть INF-файл...», «Создать INF-файл с помощью мастера...»
  и «Создать пустой INF-файл» находятся в контекстном меню узла «Редактор INF».
- **Правка.** Изменения сначала вносятся в текст в памяти, на диск файл записывается командой «Сохранить».
  Изменённый файл помечается `*` в дереве.
- **Изменение на диске.** Если файл изменён другой программой (например, после команды «Открыть в Блокноте»),
  при выборе его узла оснастка предлагает перечитать файл.
- **InfVerif.** Путь к InfVerif и режим проверки (`/w`, `/u`, `/h`, `/k`) задаются в свойствах узла
  «Редактор INF». Если путь не указан, используется InfVerif из последней установленной версии Windows Kits.
  Результаты попадают в узел «Проблемы» с источником «InfVerif».
- **Параметры и сессия** хранятся в `HKCU\Software\inf_editor`.

## Диагностика

Для отладки взаимодействия с MMC в оснастке есть трассировка вызовов. Она включается созданием пустого файла
`%TEMP%\inf_snapin_trace.log`: пока файл существует, в него дописываются вызовы MMC. Чтобы выключить
трассировку, файл необходимо удалить.
